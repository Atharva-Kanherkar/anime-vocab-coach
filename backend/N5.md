# N5 backend private preview

This is the first implementation slice of [#174](https://github.com/Atharva-Kanherkar/anime-vocab-coach/issues/174), under epic #173. It unblocks consumers with contracts and a persistent practice API. It does not complete the issue or launch a course.

The preview has six planned catalogue tracks and the 24-unit outline. Only Your Lie in April episode 1 has a fixture: an original short summary, teaching vocabulary/examples, eight objective questions and two typed tasks in separate romaji/kana renderings. Content is explicitly **unreviewed**, not published or educator-approved. Other tracks are not enrolment targets. The summary's factual source is the [official episode page](https://www.yourlieinapril.com/story/01.html); no episode dialogue, media, or synopsis text is copied.

## Run locally

Use Node 24 or later, matching CI. From `backend/`:

```sh
npm ci
npm run dev:n5
```

The harness builds the actual Worker, applies versioned production SQL migrations to local D1, and seeds local KV with synthetic sync tokens. It prints a random loopback URL. Data is ephemeral; the persistence/restart E2E uses a separate temporary persisted database. The printed token is only a local fixture and cannot access production.

The harness is loopback-only, and `wrangler.n5.jsonc` has placeholder resource IDs for local type generation. **Do not deploy this local config.** No cloud resources need to be created to run tests.

Set the URL printed by the harness, then run these checks:

```sh
n5_preview_url=http://127.0.0.1:PORT

# 401 with a typed unauthorized error
curl -i "$n5_preview_url/v1/n5/catalog"

# 200, private_preview, six track records
curl -i -H 'Authorization: Bearer avc_st_n5local' "$n5_preview_url/v1/n5/catalog"

# Enrol in kana (change to romaji to test the other rendering)
curl -i -H 'Authorization: Bearer avc_st_n5local' -H 'Content-Type: application/json' \
  -d '{"trackId":"your-lie-in-april-2014","script":"kana","idempotencyKey":"manual-enrol"}' \
  "$n5_preview_url/v1/n5/enrolments"

# 200, only the selected Japanese script and no private grading keys
curl -i -H 'Authorization: Bearer avc_st_n5local' \
  "$n5_preview_url/v1/n5/lessons/your-lie-in-april-s1-e1"

# Create an attempt; copy its id into ATTEMPT below
curl -i -H 'Authorization: Bearer avc_st_n5local' -H 'Content-Type: application/json' \
  -d '{"lessonId":"your-lie-in-april-s1-e1","contentVersion":"preview-1","idempotencyKey":"manual-create"}' \
  "$n5_preview_url/v1/n5/attempts"

# 503 voice_unavailable; no provider call or credential mint
curl -i -H 'Authorization: Bearer avc_st_n5local' -H 'Content-Type: application/json' \
  -d '{}' "$n5_preview_url/v1/n5/attempts/ATTEMPT/voice"
```

`npm run test:e2e` runs the complete answer/finish/review/export/delete flow through the Worker in both scripts, with an independent explicit answer oracle. Browser UI E2Es belong to #175/#176; these are HTTP/backend E2Es in workerd with real local KV/D1, not a mock repository.

## Contract and trust boundaries

Consumers import dependency-free wire types from `shared/n5/contracts.ts`. `shared/n5/requests.schema.json` contains the runtime-derived strict JSON Schemas. Run `npm run contracts:n5` after deliberate request changes; CI checks it with `npm run contracts:n5:check`. Backend Zod schemas are the request authority. Schema metadata imports the runtime CONTENT_VERSION, and the CI dependency-parity check requires root/backend manifests and locks to agree on Zod so the root Worker build and backend tests exercise the same validator version. Progress, review envelopes and exports have shared response types enforced at the server return boundary; export fields consistently use camelCase, including trackId, episodeId, createdAt, attemptId and objectiveId. Binding types are generated with `npm run types:n5` and checked in CI.

All routes are under `/v1/n5`. Responses have `X-N5-API-Version: 1`, `Cache-Control: no-store`, and typed `{error:{code,message,details?}}` failures. Queries are rejected except one optional `script=romaji|kana` on the lesson route. JSON bodies are streamed with a 16 KiB byte limit. Schema unknown fields, including client identity/grades, are rejected. IDs/keys/text/revisions are bounded, and each user can have at most five active attempts for the current lesson/version/pack hash. Stale attempts remain readable and deletable without blocking new practice. Per-user retry history rolls at 100 enrolment receipts and 1,000 event request receipts. Old receipts are pruned atomically; reaching these bounds never rejects a script change or observation. Retained keys preserve exact replay/conflict behavior; an evicted key is treated as a new request. These bounds are not a full public traffic policy.

Authentication uses the existing server-validated sync-token identity in KV. The web frontend must obtain its token on its trusted server or add a separately reviewed internal assertion gateway later. This API does not accept a Clerk user ID supplied by a browser. It has no cookie authentication; browser requests use an explicit bearer. Allowed CORS origins are the two AnimeVocab hosts and Chrome extension origins. A streaming page is not an allowed caller or a source of trusted scores.

| Route | Behavior |
| --- | --- |
| `GET /catalog` | Six track descriptors and preview status |
| `GET /courses/n5-foundations` | 24-unit outline and available lesson IDs |
| `POST /enrolments` | Append an enrolment preference; latest successful preference is current |
| `GET /lessons/your-lie-in-april-s1-e1` | Public teaching/assessment payload in selected script |
| `POST /events` | Idempotent watch/practice observations, never mastery |
| `POST /attempts` | Create or replay attempt; pin lesson/content hash/script |
| `GET /attempts/:id` | Owner-only answers, revision, state and result |
| `DELETE /attempts/:id` | Abandon an owned active attempt, including stale content; cascade its answer receipts |
| `POST /attempts/:id/answers` | Full answer snapshot with revision and idempotency key |
| `POST /attempts/:id/finish` | Finalise complete answers at expected revision |
| `POST /attempts/:id/voice` | Always `503 voice_unavailable` in this slice |
| `GET /me/progress` | Observations, attempts and explicit mastery=false |
| `GET /me/reviews` | Durable review events; consumerStatus=not_integrated |
| `GET /me/export` | Own course data, including typed answers |
| `DELETE /me` | Cascade-delete own course data only |

Enrolment, event and attempt creation keys are scoped per user and operation type. Enrolment history retains the latest 100 receipts, including the current preference. Episode observations are deduplicated by user/episode/kind; repeated observations with fresh keys return the existing canonical observation ID. The latest 1,000 event receipts are stored separately, so pruning them never removes observed episodes. Migration preserves original response IDs for retained legacy receipts, even when legacy duplicate observations merge; new keys use the canonical ID. Replaying identical payloads returns the original resource; conflicting payloads return 409. Retrying an older enrolment receipt does not revert the latest preference. Attempts keep their original script after a preference change. Answer keys are user-scoped across attempts: reuse on a different attempt is a conflict. Array order is part of an answer snapshot's identity. Replays return the original mutation receipt's revision; GET the attempt for current state.

Answers replace the whole snapshot; omission is removal until finalisation. A D1 compare-and-swap checks both revision and active status. Only the winning mutation nonce can create a success receipt in the transaction. Finalisation reads a pinned question hash and atomically writes one result plus review events. Review IDs are deterministic per attempt/question. A failed insert rolls the whole batch back. D1 sessions start at `first-primary` to avoid stale cross-request replica reads.

Completed results and answer snapshots cannot be changed or individually deleted through the API. Abandonment is a hard deletion of an active attempt, so GET or a repeated DELETE afterward returns 404. Account-wide deletion still removes all owned course data. The full question pack hash intentionally includes wording: prompt edits invalidate active attempts conservatively rather than silently reinterpreting them; a new creation key starts current practice. The fixture is objective practice: production needs human/model review, speaking/listening/kanji literacy remain unassessed, and mastery is always false. No objective percentage is an official JLPT score. Kana/romaji validation checks an NFKC-normalized view, folds smart apostrophes and double quotes, and accepts IME spaces, Hepburn macrons/circumflexes, and kana wave marks/ellipsis, parentheses, corner quotes and colon. Mixed script, kanji, emoji and control characters remain invalid. Stored/exported answers preserve exactly the submitted text and retry identity. Semantic answer errors include `error.details.questionId` without echoing typed text. Fixture romanisation uses plain ASCII long-vowel spellings, with pronunciation-based particles; proper names use kana in kana mode. Kana production is typed composition, not handwriting.

The outbox is durable and retry-safe on the server; SRS consumers are not implemented here. Clients must later apply events with an idempotent deck-update protocol. Do not treat repeatedly reading `/me/reviews` as authorisation to apply the same review repeatedly. No “exactly once across devices” consumer guarantee is claimed.

## Rollout, privacy and rollback

Production `wrangler.toml` is unchanged. Missing `N5_ENABLED` means disabled (404) without requiring D1. A private staging rollout must separately provision/bind `N5_DB`, apply both versioned migrations in order (`0001_n5_preview.sql`, then `0002_n5_observation_receipts.sql`), set `N5_ENABLED=1`, and set the server-owned comma-separated `N5_PREVIEW_USERS` allowlist. Empty allowlist denies everyone; missing DB returns 503 after auth. No endpoint can modify flags, allowlist or published content. Setting the flag off rolls back the route exposure while keeping course data; the original pre-N5 Worker ignores these new tables. Migration 0002 separates event receipts from observations; do not run an older N5-enabled Worker against that new layout. Roll back exposure with the flag instead. Do not drop tables to roll back code.

Typed responses are private learner data. They appear only in owner-authenticated attempts/export, never telemetry or server error logs. Preview account removal must call `DELETE /v1/n5/me` through trusted account-lifecycle code until a deletion webhook is added in a later slice. Existing vocabulary, tokens and listening usage are outside the cascade and remain intact. No mic audio or provider transcripts are collected in this PR.

Before public launch, #174 still requires reviewed full-season packs and question families, educator-approved coverage, independent production/voice grading and budgets, retention/expiry policies, season/final/delayed assessments, SRS consumers, account-lifecycle integration, telemetry and live model/learner evaluation. These are not represented by stub passes.

## Verification

```sh
npm run typecheck
npm test
npm run dependencies:n5:check
npm run contracts:n5:check
npm run types:n5:check
npm run test:e2e
npm run test:fuzz
npm run test:mutation
npx wrangler deploy --dry-run --outdir=/tmp/n5-worker-check --config wrangler.toml
```

Fuzzing uses fixed seeds with six 1,000-case domain properties and two 100-case HTTP properties; fast-check prints shrinking counterexamples and seeds on failure. Mutation testing instruments every executable validation/rendering/grading function in `src/n5/domain.ts`, with a 90% CI break threshold and no excluded mutants. It does not instrument routing/SQL, whose ownership/concurrency/rollback properties are exercised separately in workerd. Reports are generated under ignored `backend/reports/mutation/` and uploaded by CI.
