## What changed

### First-run onboarding (#77)
- A welcome page on install that is the path, not a brochure: open anime → あ → first card.
- Onboarding state is stamped on the paths a learner actually walks, not on page opens.
- The popup shows a 24-hour checklist for a fresh install and congratulates a first card
  where it happens, then never mentions it again.

### YouTube session correctness (#125, #126, #127, #128, #130, #131, #132, #133)
- A playlist advance drops the previous video's card and refuses to re-card its stale
  caption text.
- A paused video holds its card for as long as the pause lasts.
- Never undo a pause the learner owns.
- The copilot panel stays clear of the player's controls.
- The extension reports itself as linked when it is linked.

### Telemetry (#75, #111, #112)
- Acquisition funnel: landing → store → install → signup → first card.
- Learning loop: `card_shown`, `card_known`, `card_learn`, `word_saved`, `review_done`,
  `listening_started`, `install_first_run`, `extension_linked`.
- Events carry the sync token when the extension is linked, so activity is attributable
  to a learner instead of counted anonymously.
- Beacons are relayed through the service worker. A content script runs at the watched
  page's origin, where a cross-origin POST to animevocab.com is dropped by CORS after the
  preflight — silently. This also fixes the **pre-existing** loss of the extension-funnel
  counters (`first_card_created`, `first_srs_review`, `upgrade_prompt_*`,
  `checkout_started`), which had been failing the same way since they shipped.
- Every beacon carries the extension's version (`v`), so /owner's **Extension builds**
  panel shows which package the numbers come from (#159). Rows from 0.5.x read as
  "unstamped".

### Subtitles and the copilot (#151)
- Subtitles no longer arrive late or mismatched.
- Keys typed into the copilot no longer reach the player (Space/digits pausing Netflix).
- Subtitles can be turned off.

## ⚠️ Before submitting

**Update the Chrome Web Store privacy disclosures first.** Through 0.5.6 the listing's
data-use answer was "aggregate rating-prompt counters only". From 0.6.0 that is no longer
accurate: the extension reports allowlisted activity counters, associated with an account
id when linked. Bare event names only — never the word, the subtitle line, the show title
or the page URL. `PRIVACY.md` § Product counters is the text to mirror into the dashboard.

Submitting 0.6.0 against the old disclosure is a mismatch between what the listing claims
and what the code does.
