# Hosted N5 private preview

This begins frontend issue #176 under epic #173. It uses the backend foundation from #177. It does not close the full course issue: only Your Lie in April episode 1 has unreviewed teaching/practice content. The other five tracks and later units are planned. Voice, educational listening audio, season/final assessment, production grading and SRS event consumption remain follow-up work.

## Trust and rollout

`N5_WEB_PREVIEW_ENABLED=1` is a server-only opt-in. With it absent, the course routes and gateway return unavailable and the app navigation has no course entry. It is deliberately not added to production configuration by this PR.

Set the same verified learner IDs in server-only `N5_PREVIEW_USERS` on both the web service and API Worker before enabling either preview flag. An absent/empty web list permits nobody. The API Worker must separately have N5 enabled and both D1 migrations applied. Web `AVC_SYNC_KV` and API `AVC_KV` already refer to the same KV namespace. The web gateway verifies the signed-in Clerk session and uses a server-only N5 credential, sent only to the production API or an explicitly configured branch preview of the same API Worker under `*.animevocab.workers.dev`. N5 credentials use `avc_n5_` tokens and `n5token:` KV records with a one-hour absolute expiry. They never create or slide extension sync-token records or count as extension links. Valid owned course credentials are reused without writes and rotated shortly before expiry. Publishing their reverse cache pointer is best effort because parallel requests can hit KV's same-key write limit; the unique credential record must be persisted successfully. Ordinary extension/paid API routes reject these credentials. The browser never receives a bearer. No browser user ID or bearer can override the cookie identity. Origin configuration is normalized, including host casing and a trailing slash. Unrelated Workers, paths, credentials and query strings are rejected; only development permits a loopback `N5_API_ORIGIN`. The nav and course layout check only the local web allowlist. They perform no N5 KV access, token creation, profile lookup or API Worker call. The gateway also rejects non-members before credential lookup; the backend independently authorizes every data request. Misconfiguration or denial hides the pilot without breaking the dashboard. N5 uses only the locally verified Clerk session ID; course requests do not fetch a full profile or extension entitlement record. Deploy the updated API auth before enabling the web pilot.

The gateway permits the required course paths/methods, bounds JSON requests at 16 KiB and upstream JSON at 512 KiB, uses a 15-second timeout, prevents redirects, strips upstream response headers, sanitizes failures, and marks responses private/no-store. Mutation Origin must equal the request's scheme and HTTP Host (Next dev normalizes URL hostnames to localhost); untrusted forwarded-host headers are ignored. Cross-site fetches are rejected. Existing sync-token minting, billing and legacy deck APIs are unchanged.

Routes for a later extension handoff contain only non-secret identifiers:

- `/app/n5`
- `/app/n5/lessons/your-lie-in-april-s1-e1`
- `/app/n5/attempts/:attemptId`
- `/app/n5/results/:attemptId`

No browser permission or microphone access is introduced. Missing voice evidence remains not assessed, typed production needs review, and course mastery stays false.

## Draft and retry behavior

Drafts live only in this tab's sessionStorage, under `avc:n5:` namespaced keys. They are bounded, versioned and scoped by verified account, attempt, content version and pinned script; they are not put in the legacy deck snapshot. A refresh can recover unsaved text while the tab session lasts. Storage-denied/private sessions can still explicitly save to the server; closing a tab can lose work not saved to the account.

Before sending a snapshot, store its exact revision, answers and idempotency key. After a lost response, freeze editing and retry that same operation. Confirmed saves update the server revision. Unchanged acknowledged answers skip another save; a lost finish response retries finish at the same revision without another answer write. Blocked typed answers remain selectable and read-only. Discard requires confirmation. The lesson handoff offers existing active attempts. Each explicit lesson-open action reconciles the selected enrolment using a retry key; unchanged selections may add a bounded receipt. The selected script is pinned in the lesson URL, start-operation keys include it, and attempt creation sends it as an expected script. A concurrent enrolment change returns `enrolment_changed` without creating an attempt; the recovery button reloads the current course selection. If the server already holds the pending snapshot after refresh, treat it as acknowledged. A concurrent-writer conflict keeps local work visible and requires an explicit choice to replace it with server answers. A retired attempt can be discarded without deleting other history. A confirmed account switch, completion or discard clears applicable drafts. Expired or temporarily unavailable authentication hides the lesson but retains drafts for reauthentication with the same account. Clerk loading shows neutral loading text. Reauthentication links return to the current attempt. “Reload after signing in” performs a document navigation so the shared layout cannot retain an expired-session latch. Definitive finish rejections such as 404 or incomplete answers unlock editing, while uncertain network failures retain the exact finish revision for retries. Lesson resume lookups use allSettled so a concurrently discarded attempt cannot break the lesson or other resume links. Each active attempt still requires its own detail request; a richer progress API is a future optimization. Backend results remain the sole grading authority.

Watch confirmation is a learner observation, not verified playback or proficiency. The provider series link requires a separate subscription and availability check. The original recap stays hidden until watch confirmation. Course script is separate from ordinary extension/deck preferences, and each attempt keeps its original script.

## Reproduce locally

Use Node 24+, then from this directory:

```sh
npm ci
npm ci --prefix ../backend
npx playwright install chromium
npm run test:e2e:n5
```

The self-contained test starts an isolated real workerd/KV/D1 backend and Next dev on random loopback ports, shares the same real KV between them through a test-only authenticated loopback binding bridge, opens fresh Playwright profiles, and cleans them up. No browser cookie import, model key, cloud resource creation or production flag change is needed. Screenshots and logs go to `/tmp/animevocab-n5-web` (override with `N5_ARTIFACTS`). CI uploads these with the mutation report.

The browser harness uses default Turbopack (set `N5_E2E_WEBPACK=1` for the supported webpack fallback on constrained local workspaces) and verifies both scripts, mobile and desktop layout, manual watch handoff, quiz/typed results, refresh, offline draft recovery, concurrent revision conflicts, identical lost-response retries, stale-attempt discard, auth-loss draft recovery, no microphone calls, no hidden grading keys or bearer leakage, and default-off routes.

```sh
npm run lint
npx tsc --noEmit
npm run test:unit
npm run test:n5:fuzz
npm run test:n5:mutation
npm run test:e2e:n5
npx opennextjs-cloudflare build
```

Fuzzing has seven fixed-seed 1,000-case properties. Stryker runs from the repository root so its sandbox includes shared code. It instruments `src/lib/n5/core.ts`, the pure save/retry/finish state machine in `src/lib/n5/attempt-state.ts`, the server credential helper, the standalone credential rules and `shared/n5/credential.ts` with a 90% minimum, no exclusions and no uncovered mutants. Gateway authentication/CSRF/bounds have separate unit tests; React, HTTP and D1 behavior have browser/runtime tests and are not included in the mutation percentage.

## Local curl boundary probes

The browser harness runs these same probes automatically while its synthetic server is alive. Its startup log shows the random loopback port; these commands apply only to that development process, not production:

```sh
n5_web_url=http://127.0.0.1:PORT
curl -i "$n5_web_url/api/n5/catalog" # 200 with the synthetic local identity
curl -i -H 'Authorization: Bearer attacker' "$n5_web_url/api/n5/catalog" # 401
curl -i -X POST -H 'Origin: https://evil.test' -H 'Content-Type: application/json' \
  -d '{}' "$n5_web_url/api/n5/events" # 403
curl -i "$n5_web_url/api/n5/catalog?upstream=https://evil.test" # 404
# The harness restarts with the flag off before these final probes:
curl -i "$n5_web_url/api/n5/catalog" # 404
curl -i "$n5_web_url/app/n5" # 404
```

Clerk loading, signed-out expiry, wrong-account and same-owner auth-loss recovery have component tests mocking `useUser` with the dev bypass disabled. The browser harness still uses a synthetic local identity. It does not claim verification against a live Clerk test instance.

Before turning on the preview flag in any deployed environment, perform a manual sign-in/session-expiry pass with real Clerk test-instance keys. The automated synthetic browser and mocked Clerk tests do not replace this rollout check. No preview flag is enabled by this PR.


The independent web package uses a checked local mirror of the dependency-free shared credential rules, so OpenNext can preserve its standalone package boundary. Run `node scripts/sync-n5-credential.mjs` from `web/` after changing `shared/n5/credential.ts`. Web unit tests and production builds run the `--check` form and reject drift; both rule modules are behavior- and mutation-tested. No global Next/OpenNext tracing-root override is needed.
